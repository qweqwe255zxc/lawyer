# Тарифы оформления (пресеты)

Как из одного шаблона собрать плоский «Эконом» и объёмный «Стандарт».
Это главный документ по теме: если он расходится с кодом — верить коду
(`theme/tokens.css`, `app/globals.css`, `lib/preset.ts`) и поправить этот
файл.

---

## 0. Короткая версия

```ts
// content/site.config.ts
theme: {
  darkModeToggle: false,
  defaultMode: "light",
  faviconGlyph: "•",
  preset: "standard",   // ← вот это
},
```

Одно поле. Дальше:

- **не трогать** ни один компонент,
- **не дописывать** `shadow-*`, `rounded-xl`, градиенты и `bg-white/80`
  в `className` секций,
- **не править** `theme/tokens.css` под тариф — блоки
  `[data-preset="standard"]` и `[data-preset="premium"]` там уже есть.

Что ещё нужно сделать руками — раздел 3 (короткий чек-лист) и раздел 4
(готовый пример конфига).

---

## 1. Почему «Стандарт» раньше получался плоским

Это не про «плохо подобрали тени». Причин было ровно четыре, и все
четыре теперь закрыты в коде — знать их полезно, чтобы не завести их
обратно.

**1. Документация обещала API, которого не было.** В старом
`docs/section-system.md` таблица пресетов говорила: «Карточки —
`variant="elevated"`». Но `variant` карточки нельзя было задать из
конфига **ни у одной секции**: `Features`, `Gallery`, `Pricing`
хардкодили `<Card variant="framed">` прямо в JSX, а `Team`, `Steps rail`,
`Testimonials` вообще не использовали `Card`. Агент честно выполнял
инструкцию, получал плоский результат и не понимал, почему.

**2. Тени были невидимыми.** `--elevation-md: 0 4px 20px -2px rgb(0 0 0 /
0.06)` — одна плоская тень на 6% альфы. На тёплой бумаге такая тень
физически не читается. Даже там, где `elevated` реально применялся
(виджет hero, таймлайн шагов, форма в контейнере), подъёма не было
видно.

**3. Карточке негде было стоять.** `Card variant="framed"` использовал
`bg-bg` — тот же цвет, что у фона секции. А `Features` по умолчанию
живёт на `surface="surface"` (белая секция), где `--surface-card` тоже
белый. Белая карточка на белом фоне с невидимой тенью и hairline-рамкой
на 50% прозрачности — это и есть «ничего».

**4. Тариф не был выражен в коде вообще.** Не было ни поля в конфиге,
ни атрибута в DOM, ни строчки в токенах. «Стандарт» существовал только
как абзац в документации — то есть как договорённость, которую нечем
проверить и легко забыть.

Теперь: тариф — это поле `theme.preset`, атрибут `data-preset` на
`<html>`, блок в `theme/tokens.css` и таблица дефолтов в
`lib/preset.ts`. И `dev`-предупреждение, если тариф дорогой, а раскладка
плоская.

## 2. Как устроен пресет

Тариф меняет **две разные вещи**, и это важно не путать.

### 2.1. Пластику — чистым CSS, без участия компонентов

`theme.preset` → `data-preset` на `<html>` (`app/layout.tsx`) → блоки
`[data-preset="standard"]` / `[data-preset="premium"]` в
`theme/tokens.css` переопределяют «ручки глубины». Компоненты читают
только ручки и не содержат ни одного условия про тариф.

| Ручка | Эконом | Стандарт |
|---|---|---|
| `--radius-card` | 4px | 16px |
| `--radius-control` (кнопки, поля) | 2px | 12px |
| `--radius-media` (фото, карта) | 2px | 16px |
| `--radius-pill` (бейджи, прогресс) | 2px | таблетка |
| `--elevation-sm/md/lg/card-hover` | одна тень на 5–12% альфы | две тени (контактная + рассеянная), тёплый чёрный |
| `--card-bg` | фон своей секции | `--surface-card` (собственная поверхность) |
| `--card-shadow` / `--card-shadow-hover` | none / none | `md` / `lg` |
| `--card-lift` | 0 | −2px (даже у некликабельной карточки) |
| `--btn-shadow` / `--btn-lift` | none / 0 | `sm` → `md` / −1px |
| `--header-shadow` / `--header-blur` / `--header-bg` | none / none / непрозрачный | `sm` / `blur(12px)` / 82% |
| `--icon-tile-padding` | 0 (голая иконка) | 14px, фон `--badge-soft-bg`, цвет акцента |
| `--section-tint` / `--hero-tint` | none | слабый акцентный радиальный градиент |
| `--control-*` (поля формы) | подчёркивание | коробка с заливкой и радиусом |
| `--accordion-gap/bg/shadow` | 0 / нет / нет | 12px / поверхность карточки / `sm` |
| `--media-shadow` | none | `md` |
| `--popover-*` (тост, меню селекта) | 4px / без тени | 16px / `lg` |

Это работает **само**, независимо от того, что написано в `sections`.
Даже конфиг, скопированный один в один с экономовского, в тарифе
`standard` уже выглядит иначе: другие радиусы, стеклянный хедер, поля
формы коробками, подсветка секций, тост с тенью.

### 2.2. Раскладку — через дефолтные `variant` секций

Глубину физически некуда положить в табличной раскладке: рамки там
рисует CSS-grid (`border-top` / `border-left` на ячейке), а не объект.
Тень можно дать только объекту — карточке. Поэтому в дорогом тарифе
почти всё, что может быть карточкой, должно ею стать.

`lib/preset.ts` — таблица «тариф → раскладка по умолчанию»,
`components/SectionRenderer.tsx` её применяет:

```ts
variant={section.variant ?? presetDefaults(preset).features}
```

| Секция | econom | standard | premium |
|---|---|---|---|
| `hero` | `type-only` | `split` | `split` |
| `stats` | `band` | `grid` | `band` |
| `stats.containerVariant` | `flat` | `elevated` | `bordered` |
| `features` | `table` | **`cards`** | `cards` |
| `steps` | `rail` | **`numbered-nodes`** | `stack` |
| `gallery` | `register` | **`grid`** | `register` |
| `testimonials` | `quotes` | **`cards`** | `quotes` |
| `team` | `columns` | **`cards`** | `columns` |
| `pricing` | `table` | **`cards`** | `cards` |
| `faq` | `narrow` | `narrow` | `narrow` |
| `contact` | `split` | `split` | `split` |
| `contact.layout` | `plain` | **`cardContainer`** | `plain` |

**Явно указанный в конфиге `variant` всегда главнее.** Это и есть
единственная оставшаяся ловушка: конфиг обычно копируют с готового
примера, где `variant` проставлен у каждой секции экономовским
значением — и дефолты тарифа не срабатывают вообще.

Поэтому в dev-режиме на плоскую раскладку в тарифе `standard` выводится
предупреждение с готовой заменой:

```
[preset] Секция "services" (features): variant="table" — плоская раскладка
в тарифе "standard". Глубину в ней показать негде. Поставьте
variant: "cards" или уберите variant совсем — тогда возьмётся вариант
тарифа. См. docs/presets.md.
```

Если такое предупреждение появилось — это баг конфига, а не шум.

## 3. Чек-лист сборки «Стандарта»

1. `theme.preset: "standard"` в `content/site.config.ts`.
2. **Убрать `variant` из секций** — пусть работает дефолт тарифа. Указывать
   `variant` только тогда, когда нужна раскладка, отличная от тарифной,
   и это осознанное решение.
3. Запустить `npm run dev`, открыть страницу, **прочитать консоль сервера**.
   Ни одного `[preset]`-предупреждения быть не должно.
4. Дать `hero` картинку (`image: "/images/hero.jpg"`) или виджет
   (`widget: { title, badge?, metrics }`). Без них `split` молча
   откатывается на `type-only`, и первый экран остаётся голой типографикой.
   Файл должен реально лежать в `public/images/` — внешние URL запрещены,
   см. `docs/section-system.md`, раздел 2.
5. Поставить `icon` каждому элементу `features` — в этом тарифе иконка
   получает акцентную плашку, и без неё карточка выглядит пустой.
6. Дать кейсам `status` и/или `tags` — плашки в тарифе становятся
   таблетками и работают как визуальный ритм.
7. Если есть `pricing` — отметить рекомендуемый тариф `featured: true`:
   он получит акцентную рамку и усиленную тень.
8. Подобрать акцент под бренд (`--palette-accent` в `theme/tokens.css` +
   `accent` в `theme/palette.ts` — оба файла, они дублируют друг друга).
   Хвойный `#14452f` — это акцент юрбюро.

Чего **не** делать:

- не дописывать тени, радиусы, градиенты и цвета в `className` компонентов —
  любая такая правка ломает сразу оба тарифа (один получает лишнюю
  глубину, другой недостающую);
- не менять `--radius-sm` / `--radius-md`: на них свёрстана вся база,
  тариф двигает **роли** (`--radius-card`, `--radius-control`,
  `--radius-media`, `--radius-pill`), а не ступени шкалы;
- не трогать типографическую шкалу и ритм: тариф отличается глубиной и
  пластикой, а не другими кеглями и отступами;
- не включать `hoverEffect` у карточек, которые никуда не ведут — в
  наборе `cursor-pointer`, и он врёт пользователю. В «Стандарте»
  карточка и без него реагирует на курсор (`--card-lift`).

## 5. Правило для новых компонентов и правок

Любая новая «дорогая» деталь — тень, подсветка, скругление, плашка,
подъём — заводится **только** как токен: нейтральное значение в `:root`
(это Эконом) и настоящее значение в блоке `[data-preset="standard"]`.
В компонент попадает имя роли, а не число.

Практически: в `components/` не должно быть ни `shadow-md`, ни
`rounded-xl`, ни `hover:-translate-y-1` — только классы слоя глубины
(`ui-card`, `ui-button`, `ui-control`, `ui-media`, `ui-media-raised`,
`ui-popover`, `ui-accordion`, `icon-tile`) и роли-радиусы
(`rounded-card`, `rounded-control`, `rounded-pill`). Эти классы живут в
`@layer components` в `app/globals.css` — то есть обычные утилиты
Tailwind (`border-fg`, `h-full`, `mt-*`) их по-прежнему перебивают.

Проверка, что правка не сломала Эконом: переключить `preset` на
`"econom"`, собрать страницу и сравнить разметку с предыдущей версией —
измениться должны только имена классов, но не структура и не
вычисленные значения (тень `none`, радиусы 2/4px, подъём 0).

## 6. Premium

Тот же каркас, противоположный способ: глубина строится рамкой и
воздухом, а не тенью. `--radius-*` минимальные (2px), все тени `none`,
`--card-border` — приглушённый акцент (45%). Раскладки ближе к Экономy
(см. таблицу в разделе 2.2). Годится там, где тени читаются как
«дешёвый SaaS»: ювелирка, архитектура, консалтинг высокого ценового
сегмента.
