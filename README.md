# Лендинг «Ковалёв и партнёры» — шаблон

Next.js 16 (App Router, Turbopack) · TypeScript 7 · Tailwind CSS 4 · без UI-библиотек.

Проект собран как **база под будущие лендинги**: вся визуальная система живёт
в токенах, весь контент — в одном конфиге, секции подключаются массивом.

---

## Запуск

```bash
npm install
```

```bash
npm run dev
```

`cp .env.example .env.local` — если нужна реальная отправка формы.
Без env форма работает и печатает заявку в лог сервера.

## Что где лежит

| Путь | Ответственность |
|---|---|
| `theme/tokens.css` | **Все** визуальные значения: палитра, шкала, ритм, радиусы, движение + блоки `[data-preset=...]` (тарифы). Единственное место с hex |
| `theme/palette.ts` | Те же цвета и тени для мест без CSS: favicon, OG-картинка, `themeColor` |
| `app/globals.css` | Маппинг Tailwind на переменные (`@theme inline`), слой глубины (`@layer components`), база и reveal |
| `lib/preset.ts` | Таблица «тариф → раскладка секции по умолчанию» + dev-проверка плоских вариантов |
| `content/site.config.ts` | Бренд, контакты, SEO, аналитика, массив секций. **Единственный файл под замену на новом проекте** |
| `types/site.ts` | Формы данных всех секций |
| `components/ui/` | Примитивы: Button, Card, Badge, Input, Select, Accordion, Toast, Container, Section, SectionHeader, BrandMark, ThemeToggle, RevealRoot. Дизайн у них переключается пропом `variant`, а не папкой |
| `components/sections/` | Все блоки страницы. Каждый — папка одного устройства: `index.tsx` (роутер по `variant`), `variants/` (файл на дизайн), `parts/` (общие куски). Кроме секций из конфига тут же `Header`, `Footer`, `NotFound`, `Privacy` — они не проходят через `SectionRenderer`, но устроены так же |
| `components/SectionRenderer.tsx` | Реестр: тип секции → компонент |
| `components/ThemeScript.tsx`, `YandexMetrika.tsx` | Инфраструктура без разметки: анти-вспышка темы и счётчик |
| `app/api/contact/route.ts` | Приём формы: Telegram + email, антиспам, фолбэк в лог |
| `lib/seo.ts` | Metadata, JSON-LD (Organization + LegalService), навигация из секций |
| `docs/presets.md` | Тарифы оформления: как собрать «Стандарт» |
| `docs/section-system.md` | Механика секций: пропсы, варианты, реестр |

### Добавить новую секцию

1. Тип и интерфейс в `types/site.ts`, добавить в юнион `Section`.
2. Папка `components/sections/<Название>/` — `index.tsx` (роутер) +
   `variants/<Вариант>.tsx`.
3. Строка в реестре `components/SectionRenderer.tsx`.
4. Раскладки по тарифам в `lib/preset.ts`, если у секции есть `variant`.
5. Объект в `sections` внутри `content/site.config.ts`.

Больше нигде ничего подключать не нужно.

### Добавить новый вариант дизайна существующей секции

1. Файл в `components/sections/<Название>/variants/`.
2. Значение в union `variant` этой секции в `types/site.ts`.
3. Строка в `variants`-мапе внутри `<Название>/index.tsx`.

Пропустить шаг 3 не получится: мапа типизирована как `Record` по всему
union, забытый вариант ломает сборку. Подробно, с примером кода и
правилами «что в вариант, а что в parts/» — `docs/section-system.md`,
раздел 7.

### Другой дизайн хедера, футера, 404 или политики

Ровно тот же алгоритм: новый файл в `variants/` соответствующей папки
(`components/sections/Header/` и т.д.) и строка в её `index.tsx`.
Разница только в том, что поля `variant` у этих четырёх блоков в
конфиге пока нет — вариант там один, и роутер выбирает его безусловно.
Когда появится второй, ручку нужно завести в конфиге и прочитать в
`index.tsx`. Страницы в `app/` при этом не трогаются вообще: они уже
только обёртки — `metadata` плюс данные из `site.config.ts`.

## Тариф оформления

Шаблон собирает и плоский сайт, и объёмный — это **одно поле** в
`content/site.config.ts`:

```ts
theme: { /* ... */ preset: "econom" },   // "econom" | "standard" | "premium"
```

- `econom` — плоско и документно: линейки вместо карточек, теней нет,
  радиус 4px. Ровно то, что описано в разделе «Дизайн-система» ниже.
- `standard` — глубина: карточки на собственной поверхности,
  двухслойные тени, скругления 12–16px, подсветка секций, акцентные
  плашки под иконками, живой hover, стеклянный хедер, поля-коробки.
  Плюс все секции без явного `variant` переключаются на карточные
  раскладки.
- `premium` — дорого через воздух и приглушённую акцентную рамку,
  без теней, радиус 2px.

Тариф меняет **только токены и дефолтные раскладки**. Компоненты,
`tokens.css` и `SectionRenderer` руками трогать не нужно: тени, радиусы
и поверхности в компонентах не захардкожены, они приходят из ручек
`[data-preset=...]`.

**Как собрать «Стандарт» — `docs/presets.md`.** Там чек-лист, таблица
«тариф → раскладка», готовый пример конфига и разбор того, почему
раньше «Стандарт» выходил неотличимым от «Эконома». Если тариф дорогой,
а раскладка секции плоская (`features: "table"` и т.п.), dev-сервер
скажет об этом в консоли с готовой заменой.

## Дизайн-система (тариф «Эконом»)

Это не просто стилевые предпочтения — если эти правила нарушить, макет
начинает разваливаться и выглядит как обычный шаблон.

Акцент (`#14452F`) — только в шести местах: primary-кнопка, заливка
единственного CTA-блока, текстовые ссылки в контенте, focus-ring, активные
состояния (открытый аккордеон, активный пункт меню) и знак логотипа. Больше
нигде — не на иконках, не на номерах разделов, не на цифрах статистики, не на
заголовках, линейках, рамках карточек, бейджах и hover-подсветке. Иконки
всегда `--color-fg-muted`, цифры — `--color-fg` или `--color-rule-strong`.

В этом тарифе: без теней, без градиентов, без декоративной графики
(кружки, диагонали, перекрывающиеся фигуры), радиус максимум 4px, эмодзи
не используем.

Всё это — свойства **тарифа `econom`**, а не всего шаблона. В
`standard` тени, скругления и подсветка появляются по определению, и
акцент штатно расширяется ровно на два места (плашка под иконкой и
рамка выделенного тарифа в `pricing`). Единственное правило, общее для
всех тарифов: **числа глубины не пишутся в компонентах** — ни
`shadow-md`, ни `rounded-xl`, ни `hover:-translate-y-1`. Только роли
(`rounded-card`, `rounded-control`, `rounded-pill`) и классы слоя
глубины (`ui-card`, `ui-button`, `ui-control`, `ui-media`,
`ui-media-raised`, `ui-popover`, `ui-accordion`, `icon-tile`).
Хардкод ломает сразу оба тарифа: один получает лишнюю глубину, другой
недостающую.

**Поверхности.** У каждой секции есть `data-surface` (`paper` / `surface` /
`ink` / `accent`), всё внутри само подхватывает цвета через `--surface-*` —
компонентам не нужно знать, какая сейчас тема или фон. Порядок на странице:
`paper → paper → surface → paper → ink → surface → paper → accent → surface`.
Тёмный блок один (кейсы), акцентный тоже один (CTA).

**Шрифты.** Source Serif 4 — заголовки, крупные цифры, цитаты. Golos Text —
всё остальное. Третьего шрифта нет и не планируется. Курсив — только для
ссылок на нормы права (`.legal-ref`).

## Тёмная тема

`theme.darkModeToggle: false` — кнопки нет, сайт рендерится в `defaultMode`.
Токены тёмной темы в `tokens.css` при этом рабочие: переключить флаг в `true`
достаточно, чтобы получить кнопку, `data-theme` на `<html>`, сохранение в
`localStorage` и анти-вспышку. На этом проекте выключена намеренно — для
юридической тематики тёмная тема не работает на доверие.

## Форма

`POST /api/contact` → Telegram и email (Resend), оба канала независимы.
Если env не заполнены — заявка печатается в лог сервера, ничего не падает.

Антиспам: honeypot-поле `company` + минимальное время заполнения (3 с) +
ограничение 5 запросов в минуту с адреса. Боты получают `200 OK` и молча
отсеиваются.

## SEO

`robots.txt`, `sitemap.xml`, canonical, JSON-LD (Organization + LegalService),
OG-картинка через `next/og` (шрифты подтягиваются с Google Fonts, при ошибке
сети отдаётся SVG-фолбэк того же макета), favicon из `theme.faviconGlyph`.

Яндекс.Метрика: `analytics.yandexMetrikaId` — `null` означает, что скрипта на
странице нет вообще.

## Новый проект из шаблона

```bash
npm run new-project my-client
```

Копирует базу в `../my-client`, обнуляет `site.config.ts` до каркаса, правит
`package.json`. Палитра и шрифты не трогаются — их меняют руками под бренд.
Тариф в заготовке — `preset: "econom"`; для дорогого сайта поменять на
`"standard"` и дальше по `docs/presets.md`.

## Известное

**TypeScript 7** — новый нативный (Go-based) компилятор, он не отдаёт старый
JS compiler API, на который опирается штатная проверка типов в `next build`.
Поэтому в [next.config.ts](next.config.ts) включён
`experimental.useTypeScriptCli: true` — это официальный путь Next.js для TS7,
а не обходной хак; сам build без флага прямо укажет на него в ошибке. Если
для продакшена важнее стабильность инструментария, а не самая свежая версия
TS, — самый безопасный откат: `typescript@6.0.3` и убрать флаг из конфига,
без других изменений в коде.

`npm audit` показывает 3 high в транзитивных зависимостях самого Next
(`postcss`, `sharp`) — advisory по факту зацепляет диапазон версий Next
целиком, включая текущую. `npm audit fix --force` откатывает на `next@9` —
делать этого нельзя. Закроется апстримным обновлением Next.
